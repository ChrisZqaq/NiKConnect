你是资深移动端产品设计师，擅长相机与影像类工具 App 的界面设计。请为一个 Android
应用做高保真可交互原型，输出单个 HTML 文件（内嵌 CSS/JS，双击即可在浏览器打开）。

## 产品
「Nikon 相机伴侣」——手机连接尼康 Z 系列相机的工具 App。
核心差异化：让用户在手机上管理、预览、一键写入相机的「云创滤镜」（Nikon Imaging
Recipe / Picture Control）。

不是社交 App，不是修图 App，不是云盘。是一个专业摄影器材的控制面板。

## 用户
28–45 岁的尼康 Z 用户。拍 RAW，用 Lightroom，懂参数。
他们在暗环境（夜晚街拍、棚拍、暗房）里用这个 App，所以界面不能晃眼。
他们讨厌花哨，但愿意为精致的手感付费。
他们评判断一个摄影 App 的标准是：像不像一台仪器。

## 设计气质
关键词：仪器感、克制、暗房、精密、留白。
参考对象的气质（不要照抄视觉）：
- Halide Mark II 的取景器界面（信息组织方式）
- Lightroom Mobile 的深色工具栏（层级克制）
- Leica 的极简（只用必要的元素）
- Ricoh GR 的胶片色（暖而不腻）

硬性要求：
- 深色为唯一主题。背景不是纯黑，是带一点暖调的深灰（让照片不显脏）。
- 只允许一个强调色，且只用于「当前状态」和「唯一主操作」，不做任何装饰性使用。
- 数字必须用等宽字体（f/2.8、1/250、ISO 6400、35mm 这类参数要能上下对齐）。
- 圆角克制（≤ 8px）。禁止大圆角卡片堆叠、禁止毛玻璃滥用、禁止渐变大色块。
- 禁止 emoji、禁止插画、禁止卡通图标。图标用极简线性，1.5px 描边。
- 留白要敢给。宁可少放一个按钮，不要挤。
- 动效只出现在三处：传输进度、滤镜切换、快门反馈。其余全部瞬时。

## 必须实现的 6 个界面

### 1. 连接
- 顶部：App 名 + 当前状态（未连接 / 已连接 Z 6III）
- 中部：已配对相机列表（缩略图 + 型号 + 电量 + 上次连接时间），点击进入主控台
- 底部：主操作「扫描新相机」
- 有一个「连接中」的过渡状态：显示 PTP 握手的三步（建立通道 / 打开会话 / 读取能力），
  每步一个细进度条，全部完成才变绿

### 2. 主控台（Live View）
- 全屏取景画面（用一张高质量风景照占位，不要纯色块）
- 画面顶部浮层：左上返回，右上电量和信号，居中显示当前滤镜名
- 画面底部浮层，两行：
  - 第一行参数条：M | 1/250 | f/2.8 | ISO 400 | 35mm | WB 5600K
    每个参数可点击，点击后弹出该参数的横向拨盘选择器
  - 第二行：左侧「相册」图标，中间大快门按钮（圆形，双层，按下有反馈），右侧「滤镜」图标
- 快门下方一行小字：可切换 拍照 / 录像 / B门
- 画面左侧竖排小图标：峰值对焦、斑马纹、网格、直方图（可开关，开启时图标高亮）

### 3. 图库（相机内 + 手机内）
- 顶部 Tab：相机 (1,284) / 手机 (327)
- 网格视图：3 列缩略图，RAW 文件右下角有小的 RAW 角标
- 顶部筛选条：全部 / JPEG / RAW / 视频 / 已选
- 长按进入多选，进入多选后底部浮出操作条：
  「下载 12 项」主按钮 + 全选 + 取消
- 右下角悬浮按钮：进入传输队列

### 4. 传输队列（后台任务）
- 列表：每项显示文件名、尺寸、进度条、速度（MB/s）
- 单项状态：等待中 / 传输中 / 已完成 / 失败（可重试）
- 顶部汇总：3 个进行中，共 1.2 GB，预计 4 分 20 秒，平均 8.4 MB/s
- 底部：暂停全部 / 取消全部
- 关键：这个界面要能体现「后台运行」——顶部有一行小字「应用切到后台仍会继续传输」

### 5. 滤镜实验室 ★ 这是整个 App 的核心页面
- 顶部：当前滤镜大预览图（一张人像或风景，占屏幕 40%）
- 预览图上有对比控制：长按显示原图，松手恢复
- 预览图下方：滤镜名 + 作者 + 「已写入相机」状态标记
- 中部横向滚动条：滤镜缩略图卡片列表（每张卡片是同一张图套不同滤镜的小图 +
  滤镜名）。当前选中的卡片有强调色描边
- 每个滤镜卡片右上角有一个小圆点状态：未写入（空心）/ 已写入（实心）
- 底部操作区，两个按钮：
  - 次操作「在手机上预览」（GPU 渲染，快速滑动时用）
  - 主操作「写入相机」（PTP 写入，写入时显示 9 个槽位 201–209 的选择器）
- 写入过程要有明确反馈：槽位格从空到实心的填充动画，完成后卡片圆点变实心
- 顶部右上角有一个「从相机读取」按钮（把相机里已有的滤镜拉回手机）

### 6. 作品集
- 顶部：年份选择器（2024 / 2025 / 2026）
- 一张大数字卡片：「2026 年你拍了 12,847 张」
- 下面三行统计，每行左边标签右边数值，用等宽数字：
  - 最常用机身：Z 6III · 8,421 张
  - 最常用镜头：NIKKOR Z 24-70mm f/2.8 S · 5,102 张
  - 焦段偏好：35mm（31%）
- 一个横向条形图：焦段分布（14/24/35/50/85/135/200+），用强调色填充
- 一个「自动分组」列表：按拍摄日期分组的卡片
  （例：10月12日 · 外滩 · 47 张 · 2 小时 18 分），点进去是网格

## 交互要求
- 所有可点击元素都要有真实的点击反馈和状态变化，不要做成静态图
- 页面之间要能真实跳转（用 JS 控制显示/隐藏，不要用锚点）
- 至少实现三条完整走通的路径：
  1. 连接 → 主控台 → 点滤镜图标 → 滤镜实验室 → 选滤镜 → 写入相机（看到槽位填充动画）
  2. 主控台 → 点相册 → 图库 → 多选 → 下载 → 传输队列（进度条真实走动）
  3. 主控台 → 返回 → 作品集（看统计）
- 参数拨盘要能真的拖动或点击切换数值
- 传输进度用 setInterval 模拟，速度数值要有轻微抖动（真实感）

## 技术规格
- 单个 HTML 文件，内联所有 CSS 和 JS，不引用任何外部资源
- 移动端尺寸：375 × 812（iPhone 标准），在桌面浏览器里居中显示成一个手机框，
  框外深灰背景
- 图片全部用 CSS 生成的渐变/噪点占位，或 base64 内嵌极小的示例图。
  不要用外链图片（会加载失败）
- 代码要清晰分段，有注释标明每个界面

## 不要做
- 不要底部 Tab Bar（这个 App 的主入口是主控台，不是列表）
- 不要登录页、不要引导页、不要启动闪屏
- 不要「设置」页
- 不要任何付费相关元素（这是完全免费的工具）
- 不要在界面上出现「AI」「智能」这类字眼
- 不要套用现成的 UI 框架视觉（Material / iOS 原生），要自己定一套
