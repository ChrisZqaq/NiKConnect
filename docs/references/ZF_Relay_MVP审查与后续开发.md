## 审查发现

### R1 · P1：旧任务和缩略图未按连接失效

位置：`ui/MainViewModel.kt:48, 98–101, 104–129, 142–146`，`ui/MainScreen.kt:336–339`。

`disconnect()` 保留下载记录，重新连接后仍可对旧记录点击「重试」。记录只包含旧的 `PhotoObject`，没有所属连接；重试会使用新客户端和旧句柄、旧文件长度。若换卡后句柄被复用，新对象比旧对象更大，就可能只下载新对象前面一段，却按旧长度报告完成。按连接隔离 `.part` 只能避免拼接旧字节，不能阻止旧任务操作新对象。缩略图缓存同样只按句柄索引且从不清空，重连后可能显示上一连接的照片。

最小修复：连接切换时使旧任务不可重试，取消旧连接的异步工作，清空缩略图；下载前确认任务属于当前连接。第一版可以直接清空旧会话任务，完成文件仍保留在系统相册。异步结果写回前也应核对连接，避免旧任务覆盖新会话状态。

验收：连接 A 中制造失败任务，断开后接入包含相同句柄、不同内容的连接 B；旧任务无法下载 B 中的对象，缩略图刷新为 B 的内容，A 的迟到结果不覆盖 B。

### R2 · P1：连接期间退出可能阻塞主线程

位置：`camera/CameraRepository.kt:16–43, 55–60`，`ui/MainViewModel.kt:157–159`。

仓库的 `connect()` 持有对象锁执行网络申请和完整握手；`close()` 需要同一把锁。连接在后台等待相机时，若 Activity 被结束并清理 ViewModel，主线程会在 `onCleared()` 调用 `close()` 并等锁，可能持续到网络或握手超时，导致卡顿或 ANR。取消协程本身不会终止这里的阻塞 Socket 读取。

最小修复：不要在仓库锁内进行长网络等待；让正在握手的客户端也能被取消并关闭，退出无需等待握手完成。保留 PTP 指令串行发送的约束，不要一起删除协议事务锁。

验收：假相机接受 TCP 后不回复，在连接中通过 `ActivityScenario.close()` 等方式结束 Activity；主线程不等待 Socket 超时，待连接的 Socket 与网络回调被释放，不产生迟到的已连接状态。单纯退到后台不一定清理 ViewModel，不能替代这一测试。

### R3 · P2：协议断开没有传递给界面

位置：`ptp/PtpIpClient.kt:133–166`，`ui/MainViewModel.kt:92–94, 125–129`，`ui/MainScreen.kt:336–339`。

协议层超时或读包失败后会关闭双通道，这一点已有测试。但刷新/下载失败只更新错误或任务状态，界面仍为 `CONNECTED`；缩略图错误则被界面吞掉。此时没有可用连接，界面上的刷新和重试会继续失败，用户只能自行先点「断开」再连接。

最小修复：将致命连接错误同步为断开状态，提供明确的重新连接入口；区分仍有连接的单项错误和已经关闭会话的错误，不对关闭的客户端直接重试。初期手动重连即可，不急于加入自动重连。

验收：下载、刷新、缩略图三条路径分别注入断线；界面一致转为需要重连，单项不支持等非致命错误不会误断开整个会话。

### R4 · P2：跨连接遗留的下载残片没有清理

位置：`camera/PhotoDownloader.kt:24–27, 64, 73–76`，`ptp/PtpIpClient.kt:37`。

每次连接生成新的 UUID，断线保留的 `.part` 在下次连接不会复用。当前只删除成功发布的那个文件，没有清理旧连接残片的路径。多次下载中断后，已经无法使用的残片会持续占据应用缓存，直到系统清理缓存或用户手动清理。

最小修复：在确认旧连接写入已停止后清理其残片，并在启动时清理失效连接的遗留文件；只处理本应用下载缓存，不能误删正在下载的文件或已保存照片。

验收：连续 5 次下载一部分后断开重连，失效残片被回收；当前连接内允许的重试和已保存照片不受影响。

## 0.1.1 实施记录

2026-10-29 已按上述审查完成代码修复，但尚未完成真机验收：

- R1：通过会话代次取消旧任务并拒绝迟到结果；连接切换时清空旧下载记录与缩略图缓存。
- R2：仓库不再持锁等待网络；待执行的网络申请与握手客户端均可关闭，协议事务锁保持串行。
- R3：客户端跟踪活动连接状态；致命协议错误使界面返回重连入口，非致命操作错误仍保留当前会话。
- R4：断线或取消后删除不可复用残片，启动时清理遗留 `.part`；同连接可恢复任务及已发布照片不受影响。
- 相册发布现在检查 `IS_PENDING` 更新结果，更新失败不会报告成功。
- 后续复审修复：TCP 建连前即登记 Socket，建连期间取消会关闭连接且不能继续握手。
- 后续复审修复：缩略图在缓存锁内再次核对会话，避免清空缓存后旧结果回写；尚未补充 ViewModel 与缓存的实际交互测试。
- 后续复审修复：旧会话的全部任务结束后，定向清理该连接的残片，不影响新连接可重试的文件。
- 新增会话代次、握手取消和残片清理回归测试；19 项 JVM 测试与 Lint 通过。

这些结果不构成真机验收。R1 的换卡/相同句柄场景、R2 的 Activity 退出、R3 的三条断线路径、R4 的连续五次断连，以及文件哈希和存储不足仍须按下方门槛实测。

## 开发顺序与验收门槛

版本号为建议的里程碑，不表示已实现或承诺日期。只针对现有一加 + Zf 组合推进。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0.1.1 · 修好连接生命周期 | 解决 R1–R4；增加会话切换、退出、连接错误及残片清理回归测试；核实存储不足时不误报成功 | 20 张 JPEG 与存储卡源文件 SHA-256 全部一致；3 次断线重连后可恢复正常下载；连接中退出不卡住；旧任务不能作用于新会话 |
| 0.2 · 日常选片与批量传输 | 多选、串行队列、取消、重复点击防重；加载更多对象，并按实际拍摄时间展示；传输时优先下载，避免缩略图请求挤占；显示完成/失败数量与速度 | 前台一次下载 20 张，结果可逐一核对；取消后没有假完成或损坏相册项；超过 120 个对象的图库仍能访问旧照片 |
| 0.3 · 后台与锁屏 | 用户开始任务时启动 `connectedDevice` 前台服务；由服务持有传输任务和相机会话，界面观察状态；通知显示进度和取消；只在活动任务需要时保持唤醒 | 在一加真机上，锁屏 10 分钟、切其他 App、旋转屏幕后任务和界面一致；关闭相机或 Wi-Fi 时明确失败并可重新连接；完成/取消后服务和唤醒资源及时释放 |
| 0.4 · RAW 与传输性能 | 先保存 NEF 原文件，不做 RAW 解码；测量同一批文件在当前网络中的速度；有证据后才试 STA/5 GHz 或调整块大小；验证发布签名和覆盖升级 | NEF 与源文件哈希一致，下载内存不随文件大小线性增长；存储不足、换卡和升级均无已有照片丢失；速度改动有相同条件下的对照数据 |
| 后续 · 相机控制 | 先遥控快门，再实时取景，再少量必要参数；每步核对 Zf 能力和模式切换 | 快门只触发一次、退出能释放控制；取景/下载互不破坏会话。具体设计在传图稳定后再制定 |

0.3 使用 Android 的本地外设连接服务类型，需补充服务声明、`FOREGROUND_SERVICE` 与 `FOREGROUND_SERVICE_CONNECTED_DEVICE` 等适用权限，并满足启动条件。现有 `CHANGE_NETWORK_STATE` 满足其一项运行前提。前台服务不能保证抵御用户强行停止或所有厂商省电策略，仍须真机验证。依据：[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device)。

后台断线应分开验证相机待机、手机锁屏、系统切网和进程回收。不能在原因未明确时把它们全部归因于「缺少心跳」，也不能让自动重试掩盖致命协议错误。跨连接续传继续关闭，直到相机/存储卡/对象身份能可靠确认。

## 真机回归记录

每次测试记录手机型号、Android/系统版本、Zf 固件、App 版本与 Git 提交、相机菜单、频段、距离、照片总字节数、耗时和失败现象。不要记录 Wi-Fi 密码或配对凭据。

| 场景 | 检查重点 | 当前证据 |
| --- | --- | --- |
| 单张 JPEG | 打开、文件大小、SHA-256 与卡内源文件一致 | 用户已报告可下载；哈希未核验 |
| 20 张连续下载 | 文件齐全、哈希、总耗时、无覆盖 | 待测 |
| 下载中关闭相机/断开 Wi-Fi | 无假完成；重连后任务归属正确 | 待测 |
| 连接中返回退出 | 主线程响应、无残留 Socket/回调 | 待测 |
| 更换卡或相同句柄重现 | 旧任务不可重试；缓存不串图 | 待测 |
| 存储不足/相册写入失败 | 无假完成、无公开半成品、残片可清理 | 待测 |
| 锁屏/后台/旋转/进程终止 | 区分连续运行、失败与需重连；不承诺被强停后自动恢复 | 待测 |

SHA-256 对比可在电脑上完成：对存储卡源文件和从手机原样复制出的文件分别运行 `shasum -a 256 <文件>`。不要经过聊天软件压缩或图片编辑导出。

## 暂不做

不新增 FTP 第二套传输通道、账号云端、多品牌适配、RAW 解码或视频工作流。暂不统一升级依赖、并行发送 PTP 指令，也不预设换协议或换热点一定更快。对当前自用目标，这些工作不会替代连接恢复和文件完整性验证。
