## 7. 2026-11-14 追加：真机暴露的一个服务端硬约束

把已占用的槽位换成另一个方案，**不能只靠 `PATCH /camera/{guid}/{deviceId}`**：实测
`IF_IR_R_C004 -> 400`（响应体空）。原因是 `C003` 会先把方案自动塞进第一个空位，
于是 PATCH 里出现"同一方案两处"；而"换掉旧方案"在 PATCH 里又表现为移除，服务端同样拒绝。

正确顺序（已实现于 `CloudAddToCameraViewModel.addToSlot` 与 `planSlotWrite`）：

1. 目标位被别的方案占着 → `C005 DELETE` 删掉它；
2. 新方案已在别的槽位 → `C005 DELETE` 那一份，再 `C003` 重新加入（服务端会放到刚空出的低位）；
3. 重新取 `H13` 排布，`PATCH` 只发送"仍应存在的完整排布"（同一 id 只出现一次）。

改完后真机链路：`C003 200 → H13 200 → C005 200（旧方案）→ C005 200（重复那份）→ C003 201 → H13 200 → C004 200`。
